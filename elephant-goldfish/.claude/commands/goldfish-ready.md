# /goldfish-ready — 金鱼验证：就绪检查 / Goldfish Test: Ready Check

## 🐟 阶段 3，测试 C：实施就绪检查

**触发时机**：批评者审查（`/goldfish-critic`）通过并更新文档后

**角色**：扮演一位即将执行实施任务的资深软件工程师，判断文档是否提供了"一次成功"所需的全部信息

---

## ⚠️ 重要提示

这是进入实施阶段的最后一道门。如果此测试未通过，**绝对不能开始写代码**。

---

## 执行步骤

### 步骤 1：工程师角色宣告

```
👷 就绪检查模式已激活

我将扮演一位即将执行实施任务的工程师。
我会判断：仅凭这份文档，我能否在第一次尝试中成功实现该功能？

请提供最终版设计文档。
```

### 步骤 2：就绪检查清单

逐项检查以下问题。每个"否"都意味着文档需要补充。

**理解层面**：
- [ ] 我清楚地理解这个功能要解决什么问题
- [ ] 我理解成功实现后用户体验是什么样的
- [ ] 我清楚边界条件和错误情况如何处理

**技术层面**：
- [ ] 文档明确列出了所有需要修改的文件
- [ ] 文档说明了每个文件需要做什么（不需要代码，但需要说明）
- [ ] 数据流向和组件交互是清晰的
- [ ] 接口/API 规范已定义（或指向了定义它们的文件）

**实施层面**：
- [ ] 实施步骤有清晰的顺序
- [ ] 我知道如何验证每个步骤是否正确
- [ ] 我知道最终如何验证整个功能是否正确

### 步骤 3：就绪判定

**完全就绪** ✅：
```
✅ 就绪检查通过！

作为执行实施的工程师，我确认：
这份文档提供了在第一次尝试中成功实现该功能所需的全部信息。

所有检查项：[列出通过的项目]

→ 文档已就绪，请进行人工审批后使用 /implement 开始实施
```

**未就绪** ❌：
```
❌ 就绪检查未通过

如果我现在开始实施，以下问题会导致我中途卡住或做出错误假设：

1. [问题1]：需要补充 [具体信息]
2. [问题2]：需要澄清 [具体内容]

→ 请补充以上信息到文档，然后重新运行 /goldfish-ready
```

### 步骤 4：人工审批提醒

如果就绪检查通过：

```
📋 下一步：人工审批

请将设计文档 docs/FEATURE_NAME.md 分享给相关团队成员进行审阅。

获得人工审批后：
1. 在 feature_list.json 中设置 "human_approved": true
2. 将功能状态更新为 "in_implement"
3. 运行 /implement 开始实施
```

---

## 注意事项

- 通过此测试后，在 `feature_list.json` 中设置 `"ready": true`
- 人工审批是必需步骤，不能被 AI 替代
- 这份通过测试的文档将成为实施阶段的"护栏"——代码必须严格遵循它
