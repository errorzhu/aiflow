# /goldfish-test — 金鱼验证：理解力测试 / Goldfish Test: Comprehension Check

## 🐟 阶段 3，测试 A：理解力检查

**触发时机**：设计文档草稿完成后，进行第一个金鱼测试

**核心原理**：模拟一个"全新的、没有任何记忆的 AI 会话"。只凭设计文档，能否理解系统应该如何工作？

---

## ⚠️ 重要提示

此命令模拟金鱼视角。执行时，你应该：
1. **忘记**之前所有的设计讨论上下文
2. **只依赖**设计文档中明确写出的信息
3. **不要**使用任何从"大象会话"中获得的隐性知识

---

## 执行步骤

### 步骤 1：定位设计文档

询问用户：「请提供设计文档路径，或粘贴文档内容。」

### 步骤 2：纯文档理解测试

用以下视角阅读文档，然后回答：

```
🐟 金鱼视角测试 A：理解力检查

仅基于这份文档（以及它引用的文件），请回答：

1. 这个功能试图完成什么任务？（用一句话）
2. 系统目前与该功能相关的运行方式是什么？
3. 实施后，数据/信息的流向是什么？
4. 哪些现有组件会受到影响？
```

### 步骤 3：诊断并给出结论

基于以上分析，给出明确结论：

**如果文档足够清晰** ✅：
```
✅ 理解力测试通过

金鱼（新会话）仅凭此文档可以：
- 理解业务目标
- 理解技术方案
- 识别需要修改的文件

→ 可以进行下一步：/goldfish-critic
```

**如果文档存在缺口** ❌：
```
❌ 理解力测试未通过

发现以下缺口（需要补充到文档中）：
1. [缺失信息1] — 建议补充位置：第X节
2. [缺失信息2] — 建议补充位置：第X节

→ 请更新文档后重新运行 /goldfish-test
```

---

## 常见缺口类型

- **系统上下文缺失**：文档没有解释现有系统的工作方式
- **假设未显式说明**：依赖隐性知识，新会话无法获得
- **文件路径不完整**：提到"修改认证模块"但未指定具体文件
- **接口/API 未定义**：说明了"调用某服务"但未说明如何调用
- **边界条件未覆盖**：没有说明错误处理方式

---

## 注意事项

- **不要跳过此步骤**。通过此测试的文档是防止代码混乱和幻觉的核心护栏
- 如果你发现自己依赖"大象会话"的记忆来理解文档，说明文档不完整
- 测试通过后更新 `feature_list.json` 中的 `"comprehension": true`
